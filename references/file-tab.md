# File tab

## Mental model

A tab that shows one file: text in the terminal font, highlighted by its extension, selectable and copyable but not editable; Markdown rendered (or as its source); diagram files drawn (or as their source); pictures and SVGs fitted to the tab; videos and sounds with the web view's player. The file's name opens a list of its folder's files, and a bar along the bottom steps to the previous or next one, in the same tab. It reads; editing happens in the user's editor (the bar's Open button).

```
model:  TabKind::File, the file in Tab.file, its folder in Tab.cwd   (Command::OpenFile)
app:    App.file_tabs: TabId -> FileTab        (view/file_tab.rs: state, FileMessage, update, view)
read:   file_view.rs: Kind::of, stamp, read    (blocking; run via vscode::off_thread)
page:   preview/ (html.rs body, server.rs HTTP, mod.rs frame), assets/preview/{preview.js,preview.css}
        a browser Panel with Panel.file = Some(tab), id from file_tab::NEXT_PAGE
viewers: viewers.rs: Extension, install/remove, App.viewers   (Settings > Files)
links:  update/links.rs: Ctrl+click / Ctrl+right-click in a terminal, [files] open and app
tree:   view/file_tree.rs: Tree in FileTab.tree, App.file_tree (saved in session.json)
```

- **The model holds the kind, the path and its folder.** `OpenFile` emits nothing. `Tab.cwd` is the file's folder, so `pane_dir` (new terminals, the file picker, VS Code), `[tab_items] {dir}` and `{path}` work as for a terminal there. `TabSpec::File(path)` saves it, `SavedTab.file` in `session.json`, and reopening a closed one (Ctrl+Shift+R) brings it back.
- **The kind comes from the extension** (`Kind::of`): Markdown (`md`, `markdown`...), still images iced decodes (`Kind::Image`), `svg`, media (`Kind::Media`: `Media::Picture` for GIF, APNG, AVIF, HEIC and JPEG XL, which move or which iced can't decode; `Media::Video` for `mp4`, `webm`, `mov`, `mkv`...; `Media::Audio` for `mp3`, `wav`, `ogg`, `flac`, `m4a`...), a diagram language (`Kind::Diagram`: `mmd`, `dot`/`gv`, `puml`, `d2`, from `Extension::for_file`), else text. Text is decoded as UTF-8 (lossy, BOM dropped) or UTF-16 with a BOM, CRLF made LF; NUL bytes in the first 8 KB mean binary, which isn't shown.
- **Reading**: opening the tab reads the file. `Message::FileTick` (every `FILE_TICK`, only while a file tab is on screen, `shown_file_tabs`; it fires once when the subscription starts, which reads restored tabs) compares each file's `Stamp` (modified time and size) and reads it again only when it changed. One read at a time per tab (`FileTab.loading`); each read is numbered (`FileTab.reads`) and `Loaded` drops any but the latest, so a read for a file the tab has left can't land. Media isn't read at all (`Read::Media`): the page loads it from the file. A missing file is checked every tick and shows once it's made.
- **Limits**: text past `MAX_TEXT` (4 MB) is left out with a note under the bar; past `HIGHLIGHT_MAX` (1 MB) it isn't highlighted. Images past 64 MB aren't read.

## Showing

- **Text and Markdown source** are an iced `text_editor` whose `on_action` drops every edit (`Action::is_edit`), so clicks, drags, the wheel and arrows work and nothing changes. Ctrl+C / Cmd+C copies through the editor; the `copy` action (Ctrl+Shift+C) falls back to `App::file_selection` when the focused tab isn't a terminal. Lines wrap: the editor has no sideways scrolling. Highlighting is iced's `highlighter` feature (syntect through `two-face`, pure Rust regexes), keyed by the extension or, without one, the file name (`file_view::syntax`); unknown kinds fall back to plain text. `App::highlight_theme` picks InspiredGitHub on a light pane background, Base16Ocean on a dark one.
- **Scroll position across reads**: a new `Content` starts at the top, so `FileTab.scrolled` sums the wheel's `Action::Scroll` lines and replays them on the new content. Moving by keyboard isn't counted.
- **Rendered Markdown without a page** (where browser tabs don't exist, or when the page couldn't start, which a line under the bar says) is iced's `markdown` (pulldown-cmark), parsed on the UI thread when read, drawn at most `PROSE_WIDTH` wide in a scrollable. `Prose` is the `markdown::Viewer`: code blocks on `Chrome.sunken`, scrolling sideways; images from local files (relative to the document, absolute, or `file://`) via `image::Handle::from_path` / `svg::Handle::from_path`; web images show their alt text. Raw HTML isn't rendered.
- **Links** (`FileMessage::Link`): `http(s)` goes through `App::open_link` (a browser tab, or the system browser); a link to another file (`file_view::linked_file`: relative, `#section` and `?query` dropped, `%xx` decoded) opens it in a new file tab in the same pane; a folder is shown in the file manager; other schemes (`mailto:`) go to the system.
- **The bar**: the folder tree's toggle, the file's name (a button: the folder's list), its folder (`~` for home) and size, then Source / Rendered for Markdown (Source / Drawing for a diagram file, only where pages exist), Open (VS Code or the plain text editor through `open_text_file`; a picture in its usual app), Show in folder, and Reload (also F5, `App::file_key`).

## Opening files from a terminal

- **Clicking.** Ctrl+click (Cmd+click) in a terminal sends `ViewEvent::Link`; `App::clicked_at` (`update/links.rs`) takes an OSC 8 hyperlink or URL first, else a `file_at` reference that `resolve_file` finds on disk, as a `Clicked`. `App::default_open` picks the place (`OpenIn`): a URL by `[browser] open_links`, a file by `[files] open` (`"vscode"` falls back to the viewer until VS Code is downloaded).
- **The menu.** Ctrl+right-click (Cmd+right-click) on an underlined link sends `ViewEvent::LinkMenu` (only while the view's `hover` holds a link, so elsewhere it still copies or pastes). The link goes in `App.clicked` and `MenuTarget::Link` opens; `link_menu_entries` (`view/menus.rs`) lists the places, the default marked, then Show in folder and Copy. Each item is `Message::OpenClicked(clicked, how)`.
- **Viewer**: a tab already showing the file in the active workspace is selected; else a new file tab goes in the pane whose active tab is a file tab, else in a split to the right. A line becomes `FileMessage::Line`: kept in `FileTab.line` until there's text, then `go_to_line` selects it (`Content::move_to`, which scrolls the editor to it). Markdown switches to its source for it.
- **VS Code tab**: `Server::url(folder, Some(file))` (see [`browser.md`](browser.md)), placed like a link's page (`open_in_browser_pane`). The folder is the terminal's when the file is inside it, else the file's.
- **App**: `open_with` runs `[files] app` (or a program picked from Open with…) with the path as an argument; an `.app` on macOS goes through `open -a`; VS Code and editors built on it (`GOTO_EDITORS`) get `-g path:line:col`. Empty runs `open_text_file`.
- **Trap**: the output is untrusted, so a file never goes to the system's default handler, which could run it.

## The folder: its list and stepping

- `file_view::siblings` lists the files (not folders) in the file's folder, sorted ignoring case with numbers in order (`natural_key`). It runs with a forced read (opening, reload, F5, going to another file) or when the list is empty, never on the tick (folders can be large), and again when the list opens (`FileMessage::Menu` then `Siblings`).
- The list (`folder_menu`) is a popup pinned under the bar with a click catcher behind it, as in the Git tab (`git_tab::popup`, `menu_title`); Escape closes it. Nothing iced draws can cover a page, so `file_page_shown` is `None` while it's open and the page hides.
- The bottom bar (`file_steps`, only with two or more files) has the previous file's name at the left, "n of m" in the middle and the next at the right; the ends are disabled, not wrapped. Left and Right do the same through `file_key` when the tab doesn't show text (whose editor uses the arrows) and the keyboard isn't in the page.
- `FileMessage::Go(path)` clears what was shown, applies `Command::SetFile` (the model sets `Tab.file` and `Tab.cwd`, so the tab's title, its folder and the saved session follow) and forces a read. The tab keeps its page: the next publish replaces the body, and the page's script sees a new document signature and starts at the top.

## The folder tree (`view/file_tree.rs`)

- **One switch, a tree per tab.** `App.file_tree` shows trees in every file tab (the bar's first button, `TreeMessage::Toggle`; saved as `Saved.file_tree`). Each tab's `Tree` holds its root, the open folders (`expanded`) and each listed folder's `Listing` (entries, folders first in `natural_key` order, `.git` left out, at most `MAX_ENTRIES` with the rest counted, and the folder's modified time). It sits at the left of everything under the top bar, at `TREE_WIDTH`, so a page beside it just gets narrower bounds.
- **The root** is the nearest folder above the file holding `.git` (a folder, or a worktree's file), else the file's folder (`root_of`); Up makes its parent the root, keeping the old root open. Going to a file outside the root (`Tree::follow` in `Go`) forgets the tree, so the next scan finds the new one.
- **Scans run off the UI thread** (`Request::run`). A forced `Refresh` (opening, reload, F5, `Go`) or turning the tree on lists the root and every open folder and opens the folders down to the file (`reveal`). The tick's `Refresh` lists only the open folders whose modified time changed (adding, removing or renaming an entry changes it; editing a file doesn't, and needn't). Opening a folder lists just it. `Scan.asked` is the root the scan was asked about: a result for a root the tree has since left is dropped.
- **Clicks**: a file is `FileMessage::Go` (this tab shows it), a folder `TreeMessage::Fold`. Right-clicking a file sets `App.clicked` and opens `MenuTarget::Link`, the same menu as Ctrl+right-click in a terminal (its inner `RightClick` captures the press before the tab menu's).

## Pages: rendered Markdown, diagrams and media in a web view

Where browser tabs exist (`preview::AVAILABLE`: Windows, macOS), rendered Markdown, diagram files and media are a web page, so downloaded JavaScript viewers can draw what iced can't and the web view can play video and sound. Elsewhere a `Media::Picture` falls back to iced's image (its first frame) and video and sound show a note.

- **Building the body.** The read's off-thread closure also runs `file_tab::page_body`, which calls `preview::html::markdown` (pulldown-cmark with tables, footnotes, strikethrough, task lists, heading attributes, math and GFM alerts) or `html::diagram`. Fenced code is highlighted there with `syntect` and `two-face` (Base16OceanDark or InspiredGithub by `Look.dark`, background left out). A block whose language has a viewer (`Extension::for_language`) becomes `<figure class="mx-diagram" data-kind="...">` holding its escaped source when the viewer is installed, else the source with a "Download X in Settings > Files" caption. `$...$`, `$$...$$` and `math` code blocks become `.mx-math` spans. Raw HTML passes through. Media becomes `html::media`: an `<img>`, `<video controls>` or `<audio controls>` (with the name above it) whose `src` is the file's name (the `<base>` is its folder) with `?v=<Stamp::tag>`, so a changed file loads afresh.
- **Publishing.** `Loaded` calls `App::publish_page`: the first time, it takes an id from `NEXT_PAGE` (counting down from `u64::MAX`, so it never meets the model's ids) and adds `Panel::for_file(tab)` to `App.browsers`; every time, it publishes `preview::Page { folder, body, look, installed, diagram }` to the server. `file_page_shown(tab)` is the page while the tab is rendered (not Source), its text was readable, and the panel has no error; the view then lays a `BrowserHost` under the bar.
- **Agent setup tabs use the same pages** for Markdown items (see [`agent-setup.md`](agent-setup.md)); `tab_page_shown`, `page_link` and `open_page_link` serve both kinds of tab.
- **The panel is an ordinary browser panel** keyed by that id. `App::browser_tab(id)` finds its tab (`Panel.file`), so `place_browsers` places, hides, reparents and covers it like a browser tab's page, and also hides it while `file_page_shown` isn't this page. `start_browser` loads `server.url(id)` and connects the server's link channel to `browser_events`. Its events go to `file_page_message`: links (`BrowserMessage::Link`, `NewWindow`) become `FileMessage::Link`; an `Address` that isn't the page (a link the script missed) is sent back with `navigate` and handled as a link (a `fs/` URL as its file). The page isn't focused on a tab switch; a click focuses it (`page_focused`), and shortcuts reach the app through `browser::shortcuts` as for browser tabs. When the tab closes, `apply` drops its `orphaned_pages` (panel and server entry).
- **The server** (`preview/server.rs`, started by the first publish, `server::get`): 127.0.0.1 on a free port, every path under `/<32 hex token>`, one thread per connection, `Connection: close`. `page/<id>` is `head` + body + `tail` with a fresh nonce and `preview::policy`: scripts only by nonce with `'strict-dynamic'` (plus eval and wasm for the viewers), `connect-src 'self'`, images from anywhere. `page/<id>/body` and `page/<id>/version` (`"<version> <frame sig>"`) feed live updates; `POST page/<id>/link` sends the link text to the app. `app/preview.{js,css}?v=<version>` are `include_str!`'d; `ext/<viewer>/<path>` serves a viewer's folder (no `..`); `fs/<absolute path>` serves files the document links to. Files are streamed from disk (`Body::File`) and answer `Range: bytes=` with 206 and `Content-Range` (`byte_range`), which players need to seek and WKWebView needs to play video at all.
- **The frame** (`preview::head` and `tail`): `<base href>` is the document's folder as a `fs/` URL (each part percent-encoded, `C:` kept), so relative and `../` links and images resolve as on disk. The look is CSS custom properties (`preview_look`: the pane background, the interface's text, muted, sunken, border and accent colors, prose and code sizes, the terminal font's family). `window.MACARONI` carries the page path, version, frame signature, document signature (`Page::document_sig`), the dark flag, Graphviz's ink color and each installed viewer's base URL.
- **The script** (`assets/preview/preview.js`) gives headings GitHub's anchors, typesets `.mx-math` with KaTeX, and draws every figure at once (a slow viewer doesn't hold up the rest), loading each viewer the first time it's needed (a classic `<script>` or `import()`, both allowed by `'strict-dynamic'`). Every 700 ms it fetches the version (`<version> <frame sig> <document sig>`): a new frame signature reloads the page (keeping the place in `sessionStorage` when it's the same file; `history.scrollRestoration` is manual); a new version fetches the body, draws it in a hidden staging `<main>`, swaps it in and restores the scroll position, or goes to the top for another file. A picture, video or sound the web view can't decode is replaced with a note (`watchMedia`). Clicks on links: `#x` scrolls in place (the `<base>` would otherwise leave the page), anything else is POSTed to `link`.
- **Keeping up.** `Message::FileTick` also runs `restyle_pages`: a changed look (theme, font zoom) is set on the server, whose frame signature changes, so the page reloads; a switch between light and dark reads the file again (its code colors are in the body). A viewer installed or removed (`viewer_installed`) rebuilds every page (`rebuild_pages`).

## Viewer extensions (`crates/app/src/viewers.rs`)

- `Extension` is Mermaid, Math (KaTeX), Graphviz (`@viz-js/viz`), PlantUML (`@plantuml/core`, the official TeaVM build, which needs its own `viz-global.js` loaded first; importing its `themes.js` as a module registers `!theme`), and D2 (`@d2lang/d2`'s browser bundle, which starts a blob module worker with its WebAssembly inlined).
- Each is one npm tarball pinned by URL and SHA-256 (`Package`), with the files kept from it (`files`, inside the tarball's `package/`). `install` downloads it with the OS's `curl` (System32's on Windows) to `viewers/<id>.tgz`, checks the SHA-256 (`sha2`), unpacks the files with the OS's `tar --strip-components 1` into `<id>.partial`, writes `package.txt` (the URL), then swaps the folder in. `installed()` compares `package.txt` with this build's URL, so a build that pins a newer version offers the download again. `viewers::dir()` is `local_data("viewers")` (`%LOCALAPPDATA%\macaroni\viewers`, or `<MACARONI_CONFIG_DIR>/viewers`).
- Settings > Files (`Section::Viewers`, `viewer_settings`) has a Download or Remove row for each; `SettingsMessage::Viewer` goes to `App::viewer_install` (off thread, `App.viewers.busy`), which reports with `Message::ViewerInstalled`.
- **Updating a pin**: download the new tarball, check it against npm's `dist.integrity` (sha512), take its SHA-256, list its files (`tar -tzf`), and update `Package`; check the script's calls against the new version's API.

## Entry points

- "File…" in the new-tab menu and the `open_file` action (no default shortcut; it's in the command palette): `App::pick_file` opens the system file picker at the pane's folder, then `Message::OpenFile` → `App::open_file_tab`.
- The control API's `open_file` (absolute `path`, optional `tab` and `split`; errs when there's no file) and `macaroni-cli open <path> [--split right]`, which makes a relative path absolute against its own folder first.
- A Markdown link to another file.

## Traps

- **Media formats are the web view's.** WebView2 plays MP4 (H.264), WebM, MP3, WAV, Ogg, FLAC and AAC but not HEIC or most MKV; WKWebView plays MP4, MOV, HEIC and AAC but not WebM or Ogg everywhere. The note covers what doesn't play.
- **Pages draw asynchronously.** Mermaid, KaTeX and Graphviz take a moment; PlantUML and D2 several seconds the first time (their engines are large). Headless browsers with `--virtual-time-budget` don't run D2's worker, so check pages in a headless browser over the DevTools protocol (real time), not with `--screenshot` alone.
- **The `<base>` breaks `#section` links** without the script's click handler, and a page whose script failed leaves links navigating the page itself; `file_page_message` catches that from `Address`.
- **Nothing in the document may carry the nonce**: the server puts it only into `head` and `tail`, never the body. Keep it that way, or Markdown could run scripts with the server's token in reach.
- **`text_editor::Content` belongs to the UI thread** (as does a parsed Markdown `Item`, which caches spans in `Cell`s), so the off-thread read returns plain `Read` data and `file_tab::shown` builds the widgets' state on update.
- **`image::Handle::from_path` is cached by path**: an image a Markdown file links to doesn't redraw when only the image changes. The tab's own picture is read as bytes each time, so it does.
- Testing: `cargo test -p macaroni file_view` covers kinds, decoding, cutting, stamps and links (it writes to a scratch folder in the temp directory, deleted when the test passes); `preview` covers the HTML (diagrams, math, highlighting, escaping, media), the frame and policy, paths, ranges, and serving a page and part of a file over a real socket; `file_view` also covers the folder's order; `file_tree` covers finding the root, revealing the file, folder order and not listing unchanged folders again; `viewers` covers languages, the pins and hashing; `macaroni-core` has `file_tabs_open_in_the_files_folder_and_save`, the app's `session.rs` `file_and_agent_setup_tabs_come_back_as_themselves`.
